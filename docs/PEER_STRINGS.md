# Peer String Indices

The peer UI reads its text from the `PeerStrings` array in each language file under `Assets/Text/`. The array is positional: index 0 is the first entry, index 1 is the second, and so on.

This document is the authoritative reference for the peer string indices. It lists the English source text, the placeholders and button tokens that must survive translation, and the procedure for adding a new string to every language.

## 1. Format and loader behavior

Each entry is a JSON string with a numeric prefix:

```json
"PeerStrings": [
    "0: Send",
    "1: Receive",
    "2: Back"
]
```

`source/strings/strings.cpp` strips the `"<number>: "` prefix before returning the text. The numeric prefix is a human-readable index; the loader uses the array position.

- `strings::get_by_name(strings::names::PEER, index)` returns the text at `index` or `nullptr` when the entry is missing.
- The peer code passes an English fallback to every lookup, so a missing entry does not crash the UI.
- A release must still contain every index in every supported language. Missing entries silently fall back to English and are treated as a translation defect.
- Never insert or remove an entry in the middle of the array. Append new entries at the end. Inserting in the middle shifts every later index and breaks the UI.
- The prefix must match the array position. A missing or wrong prefix is a review defect even though the loader strips it.

## 2. Placeholders and tokens

Preserve these exactly. Do not translate, reorder, or add extra format specifiers.

| Token | Meaning | Notes |
| --- | --- | --- |
| `%s` | String argument | Keep one `%s` for each English `%s`. |
| `%d` | Integer argument | Used for counts and progress. |
| `%lld` | 64-bit integer argument | Used for byte counts. |
| `%06u` | Zero-padded six-digit code | Pairing code. Keep the `06` width. |
| `A:` | A button label | Literal control-guide token. |
| `B:` | B button label | Literal control-guide token. |
| `Y:` | Y button label | Literal control-guide token. |
| `+` | Plus button label | Appears in prose, not as a format specifier. |
| `[x]` / `[ ]` | Marked/unmarked marker | Generated by code, not stored in `PeerStrings`. |

A translation may reorder placeholders only if the language requires it, but the total count of each placeholder must match English. For example, `%d/%d` must remain two `%d` arguments. Do not use positional specifiers such as `%1$d` unless the code is updated to match.

## 4. Adding a string

1. Append the new entry to `Assets/Text/ENUS.json` with the next index:

   ```json
   "58: Example text"
   ```

2. Append the same index to every other file in `Assets/Text/`:

   - `DE.json`
   - `ENGB.json`
   - `ES.json`
   - `ES419.json`
   - `FR.json`
   - `FRCA.json`
   - `IT.json`
   - `JA.json`
   - `KO.json`
   - `NL.json`
   - `PT.json`
   - `PTBR.json`
   - `RU.json`
   - `ZHCN.json`
   - `ZHTW.json`

3. Translate the text. Keep the numeric prefix, placeholders, and button tokens.

4. Validate every file:

   ```sh
   for file in Assets/Text/*.json; do
     python3 -m json.tool "$file" >/dev/null || exit 1
   done
   ```

5. Confirm every file has the same number of entries and the same placeholders:

   ```sh
   python3 - <<'PY'
   import collections, json, pathlib, re
   files = sorted(pathlib.Path('Assets/Text').glob('*.json'))
   source = json.loads(pathlib.Path('Assets/Text/ENUS.json').read_text())['PeerStrings']
   placeholder = re.compile(r'%(?:0?\d+)?(?:lld|d|u|s)')
   button = re.compile(r'\[(?:A|B|X|Y|L|R|ZL|ZR|SL|SR)\]')
   for path in files:
       peer = json.loads(path.read_text()).get('PeerStrings', [])
       assert len(peer) == len(source), (path, len(peer), len(source))
       for index, (english, translated) in enumerate(zip(source, peer)):
           assert translated.startswith(f'{index}: '), (path, index)
           assert collections.Counter(placeholder.findall(english)) == collections.Counter(placeholder.findall(translated)), (path, index, english, translated)
           assert collections.Counter(button.findall(english)) == collections.Counter(button.findall(translated)), (path, index, english, translated)
   print('peer strings OK:', len(files), 'files,', len(source), 'indices')
   PY
   ```

6. Build, deploy, and check the peer screen for clipped or overflowing text.

## 5. Translation notes

- `ES.json` and `ES419.json` contain user-edited wording for indices 0-43. Do not reword those entries. Index 57 is appended separately.
- `ENGB.json` should match `ENUS.json` for the peer table.
- Keep the peer terminology consistent with the rest of the language file. For example, use the same word for "backup", "save", and "user" that the file already uses.
- Do not add trailing spaces or non-breaking spaces. Use a normal ASCII space.
- Do not add a byte-order mark. The files are UTF-8 without a BOM.
- The control-guide strings use two spaces between entries (`A: Select  B: Back`). Preserve the spacing so the guide does not look cramped.
- Some languages need more width. The peer header renders at 20 px and the menu at 23 px; very long translations may clip. Prefer concise wording over literal translation.
